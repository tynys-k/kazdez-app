# Резервная копия и проверка восстановления

Supabase делает копии сам. Но копия, из которой ни разу не восстанавливались, —
это не копия, а надежда. Вся выручка, клиенты и история лежат в одной базе,
поэтому проверить восстановление нужно **один раз честно**, а дальше повторять
раз в квартал.

Полчаса работы против потери всего.

---

## Раз в квартал: выгрузить копию

```bash
npm run db:backup
```

Перед первым запуском нужна строка подключения:

1. Supabase → **Project Settings → Database → Connection string → URI**
2. Подставить в неё пароль базы.
3. Задать переменную окружения:

   PowerShell:
   ```
   $env:SUPABASE_DB_URL = "postgresql://postgres:ПАРОЛЬ@db.xxxx.supabase.co:5432/postgres"
   ```

   Git Bash:
   ```
   export SUPABASE_DB_URL="postgresql://postgres:ПАРОЛЬ@db.xxxx.supabase.co:5432/postgres"
   ```

Строка содержит пароль от базы. Она живёт только в текущем окне терминала —
не сохраняй её в файлы репозитория.

В `backups/` появятся два файла: схема и данные. Папка исключена из git —
в ней телефоны и адреса клиентов.

**Скопируй файлы туда, где они переживут потерю доступа к облаку:** внешний
диск или другой облачный аккаунт. Копия, лежащая рядом с оригиналом, не спасает.

---

## Один раз честно: проверить, что копия разворачивается

Смысл не в том, чтобы файл существовал, а в том, чтобы из него поднялась
работающая база.

1. Создай **второй проект** в Supabase (на бесплатном тарифе их можно два).
   Назови `kazdez-restore-test`.
2. Возьми его строку подключения — так же, как в шаге выше.
3. Залей схему, затем данные:

   ```bash
   npx supabase db push --db-url "postgresql://...тестовый..." --file backups/kazdez_..._schema.sql
   npx supabase db push --db-url "postgresql://...тестовый..." --file backups/kazdez_..._data.sql
   ```

   Если `db push` не принимает файл в твоей версии CLI — залей содержимое
   файлов через SQL Editor тестового проекта, сначала схему, потом данные.

4. Сверь количество строк. В **обоих** проектах выполни один и тот же запрос:

   ```sql
   select 'jobs' as t, count(*) from public.jobs
   union all select 'clients', count(*) from public.clients
   union all select 'report_chemicals', count(*) from public.report_chemicals
   union all select 'money_moves', count(*) from public.money_moves
   union all select 'tech_expenses', count(*) from public.tech_expenses
   union all select 'chemicals', count(*) from public.chemicals
   union all select 'chemical_purchases', count(*) from public.chemical_purchases
   union all select 'job_helpers', count(*) from public.job_helpers
   order by t;
   ```

   Числа должны совпасть. Если где-то расходится — копия неполная, и это надо
   выяснить **сейчас**, а не в день аварии.

5. Удали тестовый проект.

---

## Что проверка НЕ покрывает

- **Файлы в Storage** (фото-подтверждения работ) в дамп базы не входят.
  Их выгружать отдельно, из раздела Storage.
- **Пользователи и пароли** (`auth.users`) — часть системной схемы. При
  восстановлении в новый проект вход придётся заводить заново.

Это не повод не делать копию. Это повод знать заранее, что именно придётся
восстанавливать руками.
